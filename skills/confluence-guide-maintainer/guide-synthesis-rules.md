# Guide Synthesis Rules

## 목적

`page` 타입 문서가 쌓이면, 연관된 page들을 하나의 스토리로 엮는 `guide` 타입 문서를 생성한다.
`guide` 문서는 독자가 목적을 가지고 처음부터 끝까지 따라갈 수 있는 단계형·종합형 문서다.
개별 page 문서의 내용을 그대로 복사하지 않는다. 각 단계를 연결하는 흐름과 링크를 제공한다.

---

## 생성 조건 (모두 충족해야 함)

1. 동일한 도구 또는 주제 영역에 `page` 타입 문서가 **3개 이상** Confluence에 존재한다.
2. 해당 page들이 자연스러운 학습 흐름(입문 → 사용 → 심화)을 구성한다.
3. 동일한 흐름을 이미 다루는 `guide` 타입 문서가 없다.
4. 이 위키의 대상 독자(바이브 코딩, 학습, 개인 앱 개발)에게 직접 유용한 내용이다.

---

## 클러스터링 기준

연관 page들을 그룹화하는 절차:

1. Index 페이지(Claude Code Index, Gemini Index 등)에서 같은 Index 하위에 속한 page들을 1차 그룹으로 묶는다.
2. 제목의 주제 영역(설치, 명령어, 자동화, 에이전트, 컨텍스트 등)으로 2차 세분화한다.
3. page 간 논리적 선후 관계(A를 해야 B가 가능)가 있으면 흐름 후보로 분류한다.
4. **3개 미만의 그룹은 guide를 생성하지 않는다.**

---

## 스토리 유형

| 유형 | 설명 | 대표 흐름 |
|------|------|----------|
| 입문 여정 | 처음 설치부터 첫 성공 경험까지 | 설치 → 첫 실행 → 기본 명령어 사용 |
| 기능 심화 | 핵심 기능들을 엮어 완성된 워크플로우 구성 | 명령어 → 스킬 → Subagent 활용 |
| 자동화 구성 | 반복 작업을 자동화하는 설정 흐름 | Hooks → Memory → 자동 실행 패턴 |
| 컨텍스트 관리 | 긴 작업에서 컨텍스트를 유지·복원하는 흐름 | Memory → Sessions → Checkpointing |
| 앱 개발 여정 | 아이디어를 앱으로 만드는 전체 흐름 | 프롬프트 설계 → 코드 생성 → 디버깅 |

## Guide 문서 구조

```
도입부 (2~3문장)
- 이 가이드를 읽고 나면 무엇을 할 수 있는지
- 왜 이 기능들을 함께 이해하는 것이 중요한지

## 시작 전 준비
- prerequisites에 해당하는 page 링크와 한 줄 설명

## 1단계: <첫 번째 주제>
- 핵심을 1~2문장으로 설명
- 자세한 내용은 → [page 제목](page 링크)

## 2단계: <두 번째 주제>
...

## 전체 흐름 요약
- 단계별 흐름을 한눈에 볼 수 있는 간략한 요약

## 다음으로 배울 것
- next에 해당하는 page/guide 링크

## 관련 가이드
- related에 해당하는 page/guide 링크
```

---

## Guide 제목 규칙

- `[Guide]` 접두사 사용
- 목적 중심 제목: 독자가 이 가이드를 읽고 **할 수 있게 되는 것**을 제목으로
- 형식: `[Guide] <도구명>으로 <목적> 만들기 / 시작하기 / 구성하기`
- 예시:
  - `[Guide] Claude Code로 자동화 워크플로우 만들기`
  - `[Guide] Claude Code 컨텍스트 관리 완전 정복`
  - `[Guide] Gemini CLI로 바이브 코딩 시작하기`

## metadata 설정

guide 문서 생성 시 `wiki.metadata`는 아래 기준으로 설정한다.

```json
{
  "docType": "guide",
  "audience": "beginner",
  "status": "published",
  "prerequisites": [<선행 page ID 목록>],
  "next": [<다음 단계 page/guide ID 목록>],
  "related": [<연관 guide ID 목록>],
  "lastReviewedAt": "YYYY-MM-DD",
  "reviewCycleDays": 90,
  "keywords": [<도구명, 워크플로우명, 핵심 기능명>]
}
```

## 1회 실행당 생성 제한

한 번의 실행에서 `guide` 문서는 **최대 1개** 생성한다.

더 많은 후보가 있을 경우:
- 가장 독자 가치가 높은 1개를 선택해 생성한다.
- 나머지 후보는 `wiki-targets.md` 에이전트 발견 주제 로그에 `PENDING`으로 기록한다.

---

## 후보 우선순위

동시에 여러 guide 후보가 있을 때 아래 기준으로 순위를 매긴다.

| 기준 | 높은 우선순위 | 낮은 우선순위 |
|------|------------|------------|
| 독자 접근성 | 초보자가 바로 따라할 수 있음 | 선행 지식 필요 |
| 스토리 완결성 | 시작~완료가 하나의 흐름으로 연결 | 중간 단계만 커버 |
| page 수 | 더 많은 관련 page 보유 | page 수 적음 |
| 위키 목적 관련성 | 바이브 코딩·학습·앱 개발에 직결 | 고급·운영 주제 |
